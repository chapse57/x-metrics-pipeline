The API's database login cannot write. Two layers, each shown failing on its own.
Recorded 2026-09-23 against the docker compose stack (postgres:16), login xmetrics_api.

Layer 1 — the login's sessions are read-only (ALTER ROLE ... SET default_transaction_read_only = on, pg/roles.py):

$ docker compose exec postgres psql -U xmetrics_api -d xmetrics \
    -c "INSERT INTO raw.runs (run_id, started_at, source, source_db) VALUES ('x', now(), 'x', 'x');"
ERROR:  cannot execute INSERT in a read-only transaction

Layer 2 — switch layer 1 off from inside the session; the role still has no write grant
(xmetrics_reader: USAGE + SELECT + EXECUTE only, pg/schema/005_reader_role.sql):

$ docker compose exec postgres psql -U xmetrics_api -d xmetrics \
    -c "SET default_transaction_read_only = off" \
    -c "INSERT INTO raw.runs (run_id, started_at, source, source_db) VALUES ('x', now(), 'x', 'x');"
SET
ERROR:  permission denied for table runs

Layer 1 is a setting a session can change. Layer 2 is a missing privilege it cannot.
tests/test_api.py::test_reader_role_cannot_write repeats layer 2 for INSERT, UPDATE, DELETE,
CREATE TABLE and the migration ledger on every test run.
